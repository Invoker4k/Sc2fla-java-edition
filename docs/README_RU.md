**Конвертер файлов Supercell (`.sc`) в проект Adobe Animate (`.fla`) на Java.**

![Демонстрация работы](../media/preview.gif)

---

## Описание

Программа читает игровые `.sc`-файлы (используемые в играх Supercell, например, Clash of Clans или Brawl Stars) и преобразует их в формат **XFL**, который затем упаковывается в `.fla`-архив.

---

## Требования к системе

- **Java 17** или выше.
- **PVRTexToolCLI** – утилита от Imagination Technologies для преобразования сжатых KTX-текстур в PNG.
- **SctxConverter** (только для файлов с текстурами SCTX) – утилита для декодирования SCTX-формата. На Windows используется `SctxConverter.exe`, на Linux запускается через **Wine**.
- Положите исполняемые файлы в ту же папку, что и `sc2fla.jar`, или укажите путь через переменные окружения `PVRTEXTOOL_PATH` и `SCTXCONVERTER_PATH`.

> **Примечания:**
> - Если PVRTexToolCLI отсутствует, конвертация KTX-текстур будет пропущена (будут созданы пустые изображения).
> - Если SctxConverter отсутствует, SCTX-текстуры не будут декодированы.
> - На Linux для работы SctxConverter требуется установленный **Wine**. Если Wine не найден, программа выдаст ошибку.

- **Оперативная память:** Конвертация больших файлов (например, `ui.sc` из последних версий игры) может потребовать до **4 ГБ ОЗУ**.

## Установка и запуск

1. **Скачайте** последнюю версию `sc2fla.jar` из релизов (или соберите самостоятельно, см. раздел [«Сборка»](#сборка-из-исходников)).
2. **Убедитесь**, что все необходимые утилиты доступны (см. выше).
3. Запустите конвертацию из командной строки:

   ```bash
   java -jar sc2fla.jar -d <путь_к_файлу.sc> [-l <лог_файл.txt>] [-t <N|all>] [-fps <N>] [-r] [-e <имена>] [--export-list <файл>]
   ```

   Параметры в квадратных скобках `[]` являются **необязательными**.

### Параметры

| Параметр | Описание |
| :--- | :--- |
| `-d <файл>` | **Обязательный.** Путь к `.sc`-файлу, который нужно конвертировать. |
| `-l <файл>` | Сохранять весь вывод консоли (информация, предупреждения, ошибки) в указанный текстовый файл. |
| `-t <N\|all>` | Количество потоков для параллельной обработки KTX-текстур. По умолчанию (`all`) – используются все доступные ядра процессора. Укажите число, чтобы ограничить нагрузку. |
| `-fps <N>` | Принудительно установить частоту кадров (FPS) в выходном проекте. По умолчанию программа автоматически определяет FPS из исходного файла. |
| `-r`, `--repack` | Включает дедупликацию спрайтов – одинаковые (побайтово, по MD5) текстурные фрагменты сохраняются один раз, что уменьшает размер выходного `.fla`. По умолчанию выключено. |
| `-e <имена>` | Конвертировать только перечисленные экспортнеймы, через запятую, без пробелов вокруг запятых необязательно (`-e "hero, ui_button, effect_spawn"`). Всё, что не используется выбранными экспортами, в `.fla` не попадёт. |
| `--export-list <файл>` | То же самое, что `-e`, но список экспортнеймов берётся из текстового файла — по одному имени на строку. Строки, начинающиеся с `#`, игнорируются (комментарии). |
| `-h` или `--help` | Показать справку по использованию. |

`-e` и `--export-list` можно использовать одновременно — списки объединяются. Если запрошенное имя не найдено среди экспортов файла, программа выведет предупреждение и продолжит с остальными.

### Примеры

```bash
# Базовая конвертация
java -jar sc2fla.jar -d assets/ui.sc

# С сохранением лога и использованием 4 потоков
java -jar sc2fla.jar -d assets/ui.sc -l conversion.log -t 4

# Принудительная частота кадров 60 FPS
java -jar sc2fla.jar -d assets/ui.sc -fps 60

# С включённой дедупликацией
java -jar sc2fla.jar -d assets/ui.sc -r

# Только конкретные экспорты
java -jar sc2fla.jar -d assets/characters.sc -e "hero,hero_icon,hero_attack_effect"

# Список экспортов из файла
java -jar sc2fla.jar -d assets/characters.sc --export-list wanted_exports.txt
```

После успешного выполнения рядом с исходным файлом появится файл с тем же именем, но с расширением `.fla` (например, `assets/ui.fla`).

## Особенности работы с текстурами

Конвертер поддерживает все три формата текстур:

- **KTX** – стандартный сжатый формат, конвертируется через `PVRTexToolCLI`.
- **SCTX** – проприетарный формат Supercell, для декодирования требуется `SctxConverter.exe`.
  На Linux программа автоматически определяет наличие Wine и запускает `SctxConverter.exe` через него. Если Wine не установлен, будет выведена ошибка.
- **RAW** – обычные сырые пиксели.

## Геометрия фигур (Shape)

Каждая фигура (`Shape`) в `.sc`-файле состоит из одной или нескольких команд отрисовки (`ShapeDrawBitmapCommand`) — по сути, кусков текстуры произвольной формы. У каждой команды есть набор вершин, но сам файл не гарантирует, что они идут по порядку контура. Поэтому конвертер сначала восстанавливает геометрию сам:

1. **Собирает контур.** Вершины команды сортируются по углу вокруг их центра масс — получается простой выпуклый контур по часовой стрелке, независимо от того, в каком порядке они лежали в файле.
2. **Определяет тип заливки.** Если все точки контура указывают на одну и ту же точку текстуры (одинаковые UV), это заливка сплошным цветом — конвертер берёт цвет пикселя и рисует контур как обычную векторную фигуру (треугольным веером, где каждый треугольник — отдельное ребро `Edge`). Если нет — это кусок текстуры, и контур используется как маска, по которой из атлaса вырезается нужный фрагмент.
3. **Вычисляет позицию фрагмента на сцене.** Чтобы понять, где и как именно разместить вырезанный кусок текстуры (`BitmapInstance`) на сцене, координаты вершин в текстуре сопоставляются с их координатами на сцене методом наименьших квадратов — сразу по всем точкам контура, а не по первым двум попавшимся. Дополнительно определяется, не отзеркален ли фрагмент по UV, а угол поворота округляется до ближайших 90°. Такой подход устойчив даже к «вырожденным» фигурам (например, вытянутым в линию), на которых оценка по двум точкам могла давать смещённый и неправильно смасштабированный результат.

## Маски и blend mode

- **Маски.** В формате SC маска — это не свойство слоя, а отдельный псевдо-объект без геометрии (`MovieClipModifierOriginal` с тегом `Mask`, `Masked` или `Unmasked`), который лежит прямо в списке дочерних элементов мувиклипа вперемешку с обычными Shape/MovieClip/TextField. Он работает как переключатель: всё, что идёт в списке **после** него, до следующего такого объекта, попадает в соответствующий режим — «это маска», «это маскируемый слой» или «обычный слой». Конвертер проходит по списку детей каждого мувиклипа, отслеживает эти переключения и проставляет слоям в `DOMTimeline` те же атрибуты, что расставил бы сам Adobe Animate: `layerType="mask"` для слоя-маски, `layerType="masked"` и `parentLayerIndex` — для слоёв, которые она маскирует.
- **Blend mode.** У каждого дочернего объекта в мувиклипе есть числовой код режима смешивания (0 — Normal, 2 — Multiply, 3 — Screen, 6 — Add, 12 — Overlay и т.д.). Конвертер переводит этот код в текстовую константу, которую понимает Animate (`multiply`, `screen`, `add`...), и записывает её в атрибут `blendMode` у соответствующего `DOMSymbolInstance`.

## Выборочный экспорт по именам

Флаги `-e` и `--export-list` позволяют собрать `.fla`, содержащий только нужные экспортнеймы и всё, что им реально требуется (дочерние MovieClip, Shape, TextField — рекурсивно), не трогая остальную часть файла. Это полезно для больших файлов вроде `ui.sc` или `characters.sc`, когда нужен всего один-два персонажа или эффекта.

## Что происходит внутри?

Программа выполняет следующие шаги:

1. **Загрузка .sc** – распаковывается сжатый контейнер, читаются метаданные (экспорты, матричные банки, текстуры, фигуры, мувиклипы).

2. **Определение нужных объектов** – если заданы `-e`/`--export-list`, от каждого выбранного экспортнейма выполняется обход зависимостей, иначе обрабатываются все экспорт-неймы файла.

3. **Предварительная конвертация текстур** – все сжатые текстуры преобразуются в png. Конвертация выполняется параллельно в несколько потоков (задаётся параметром `-t`).

4. **Обработка фигур (Shape)** – каждая фигура разбивается на команды рисования с текстурой; вершины каждой команды пересобираются в выпуклый контур по углу вокруг центроида. Если фрагмент имеет размер 1×1 пиксель, он заменяется сплошной заливкой (SolidColor). Иначе создаётся отдельный DOMBitmapItem в библиотеке XFL, а позиция вычисляется по методу наименьших квадратов.

5. **Обработка текстовых полей (TextField)** – переносятся шрифт, размер, выравнивание, обводка (`GlowFilter`/`DropShadowFilter`), режим рендеринга шрифта и авто-расширение текста.

6. **Обработка мувиклипов (MovieClip)** – создаются слои (по одному на каждого дочернего объекта). Для каждого индекса кадра создаётся отдельный `DOMFrame`, даже если он пуст, — временная структура анимации сохраняется точно. Для каждого элемента применяются матрицы трансформации, цветокоррекция, blend mode и (если распознаны) маски.

7. **Дедупликация (опционально, флаг `-r`)** – спрайты группируются по полному MD5-хешу их пиксельных данных, что исключает ложные совпадения; остаются только уникальные экземпляры, ссылки на дубликаты заменяются на них.

8. **Построение XFL-документа** – формируется DOMDocument.xml, xml файлы, ресурсы png,dat для текстур; кеш зависимостей (SymDepend.cache). Все XML-файлы сжимаются с максимальной степенью сжатия (уровень 9) для уменьшения размера итогового .fla.

9. **Упаковка в .fla** – все файлы архивируются в .fla. png файлы сохраняются без сжатия (метод STORED). Все временные данные хранятся в памяти; временные папки на диске не создаются.

## Сборка из исходников

Для сборки проекта вам потребуется:
* **JDK 17** или новее.
* **Apache Maven** (версия 3.6+).

Клонируйте репозиторий и выполните:

```bash
git clone https://github.com/Invoker4k/sc2fla-java-edition.git
cd sc2fla-java-edition
mvn clean package
```

В папке `target/` появится исполняемый JAR-файл с именем `sc2fla.jar`.
